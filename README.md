# seunghoojin.com

The personal website of Andrew SeungHoo Jin: a static site built with
[Eleventy](https://www.11ty.dev/) on the "Andrew SeungHoo Jin" design system.

## Run locally

Requires Node.js 22 or later, and `pdftoppm` (from Poppler) to render PDF
covers (`brew install poppler` on macOS).

```bash
npm install
npm start      # http://localhost:8080, rebuilds on save
npm run build  # writes the site to _site/
```

## Layout

```
src/
  _data/sections.js      Sections of the home board: order, title, lead, links
  _data/site.js          Name, subtitle, footer date
  _includes/             Masthead, footer, section box, page layouts
  index.njk              Home board
  admin/                 The editor at /admin/ (Decap CMS); not linked from the site
  section-index.njk      One SectionIndex page per section
  <section>/<slug>/      One folder per entry (see below)
  design-system/         Copy of seunghoojin-design-system/{css,js,fonts,assets}
seunghoojin-design-system/  The design system originals; do not edit here
cms-auth/                   Cloudflare Worker: GitHub sign-in for the editor
```

## Adding an entry

Create a folder under its section and put an `index.md` in it:

```
src/projects/my-project/
  index.md
  article.pdf    optional: the full article
  cover.jpg      optional: the card image
```

```yaml
---
title: "My Project"
section: projects           # must match the folder and a slug in sections.js
date: 2026-11-02            # shown as "2 November 2026"; sorts newest first
period: ""                  # optional, replaces the date: "March 2022 – present"
order: 1                    # optional, sorts entries that have no date
snippet: "The opening of the article, shown on the board. Markdown links allowed."
image: "cover.jpg"          # optional, a file in this folder
focus: "50% 30%"            # optional, the crop point when the image is cropped
pdf: "article.pdf"          # optional, a file in this folder or a full URL
---

The article text, in Markdown.
```

The folder path is the entry's URL (`/projects/my-project/`), and files in the
folder are served from it, so the card, the article page and its PDF are linked
by sitting together. When an entry has a local PDF and no image, page 1 of the
PDF is rendered at build time and shown on the article page with an
"Open the PDF" button.

## Editing in the browser

`/admin/` is an editor ([Decap CMS](https://decapcms.org/)) for the entries
above. It has one collection per section in `src/_data/sections.js` (the
config is generated by `src/admin/config.yml.11ty.js`), and it writes the same
files you would: `src/<section>/<slug>/index.md`, with uploaded images and PDFs
in that folder. Publishing an entry commits it to `main`, which deploys the
site. The Focus field shows the image at the box width with the part in view
outlined; select a point or use the arrow keys to move it.

The file picker lists every file in the entry's folder, `index.md` included
(and, for a new entry, the section's `*.11tydata.json`). Pick only images and
PDFs there, and do not delete the other files.

To try it locally without signing in, run both servers and open
http://localhost:8080/admin/:

```bash
npm start
npm run cms    # decap-server: the editor writes to this checkout
```

On the live site the editor signs in with GitHub through a small OAuth proxy
in `cms-auth/`, a Cloudflare Worker, because GitHub Pages cannot keep the
OAuth client secret. To set it up once:

1. In `cms-auth/`, sign in to Cloudflare and deploy the Worker:
   `npx wrangler@4.158.0 login`, then `npx wrangler@4.158.0 deploy`. The
   deploy prints the Worker's URL,
   `https://seunghoojin-cms-auth.<your-subdomain>.workers.dev`.
2. Create a GitHub OAuth App (Settings, Developer settings, OAuth Apps) with
   homepage `https://seunghoojin.com` and callback URL `<Worker URL>/callback`.
3. Store the app's credentials as Worker secrets, typed at the prompts:
   `npx wrangler@4.158.0 secret put GITHUB_CLIENT_ID` and
   `npx wrangler@4.158.0 secret put GITHUB_CLIENT_SECRET`.
4. Set `OAUTH_PROXY` in `src/admin/config.yml.11ty.js` to the Worker's URL
   and push.

Only GitHub accounts with write access to `seunghoojin/website` can publish.

## Deployment

Pushing to `main` builds the site with GitHub Actions and publishes it to
GitHub Pages (`.github/workflows/deploy.yml`). The footer's "updated" date is
the build date.
